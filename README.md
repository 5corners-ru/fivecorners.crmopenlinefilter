# fivecorners.crmopenlinefilter

Модуль **5 УГЛОВ** для Bitrix24 on-premise. Добавляет в стандартный фильтр Лидов и Сделок CRM поле «Чат с клиентом прочитан?», позволяющее отобрать записи с непрочитанными (или, наоборот, прочитанными) сообщениями открытых линий.

## Зачем

Штатно Bitrix24 показывает бейдж «чат с клиентом: НЕПРОЧИТАННЫЙ» на карточках Лидов/Сделок в канбане, но не даёт отфильтровать по этому признаку список/воронку. Модуль закрывает этот пробел.

## Как это работает

Модуль **не отслеживает чаты сам**. Всю работу уже делает ядро Bitrix24: при получении/прочтении сообщения открытой линии ядро CRM (`crm/lib/activity/provider/openline.php::syncBadges()`) в реальном времени пишет/убирает бейдж `TYPE=open_line_status, VALUE=not_read_chat` в штатную таблицу `b_crm_item_badge` — ту самую, из которой берётся жёлтый лейбл на карточках канбана.

Модуль подменяет DI-сервис `crm.filter.factory` (штатная точка расширения `Bitrix\Crm\Filter\Factory`) своим классом `FiveCorners\CrmOpenlineFilter\FilterFactory`, который:

1. добавляет в фильтр Лидов и Сделок псевдо-поле-чекбокс «Да/Нет»;
2. при применении фильтра транслирует его в `ID IN (...)` / `ID NOT IN (...)` по данным из `b_crm_item_badge`.

Подробности — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Установка

1. Скопировать модуль в `/local/modules/fivecorners.crmopenlinefilter/` (или `/bitrix/modules/` при установке через Marketplace).
2. Marketplace → Установленные решения → «5 УГЛОВ. Фильтр Лидов/Сделок по непрочитанным чатам открытых линий» → «Установить».
3. Список Лидов или Сделок → «Фильтр» → «Добавить поле» → «Чат с клиентом прочитан?».

Требуется установленный модуль `crm`.

## Удаление

Marketplace → Установленные → модуль → «Удалить» (двухшаговое удаление по канону). Модуль не хранит собственных данных — чекбокс «сохранить настройки» ни на что не влияет.

## Важно: только один модуль может владеть `crm.filter.factory`

DI-сервис `crm.filter.factory` — синглтон. Если на портале уже установлен другой модуль, тоже подменяющий эту фабрику (например, `dbogdanoff.crmfilter`), их фильтры конфликтуют — работать будет только последний зарегистрированный `OnProlog`-обработчик. Перед установкой деинсталлируйте конкурирующие модули с тем же расширением.

## Структура

- `install/index.php` — DoInstall/DoUninstall, двухшаговое удаление, регистрация `OnProlog`-обработчика.
- `lib/EventHandler.php` — переустанавливает подмену `crm.filter.factory` на каждый запрос (ServiceLocator не переживает между хитами).
- `lib/FilterFactory.php` — логика фильтра: псевдо-поле + перевод в `ID IN/NOT IN` по `b_crm_item_badge`.
- Собственных таблиц, UF-полей, admin-страниц и агентов у модуля нет.
